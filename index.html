MENA Threat Actor Tracker — Multi-Stage CTI Repository

Objective: Built and maintain a structured, citation-backed threat-actor tracking repository for the MENA region, combining OSINT research, MITRE ATT&CK TTP mapping, and Sigma detection-coverage auditing into one reproducible pipeline — with a scheduled automation layer that keeps it current without re-researching the entire threat landscape every cycle.

Tools & Tech: Multi-stage orchestration (CTI research, detection engineering), MITRE ATT&CK & Navigator, Sigma, Python/openpyxl, scheduled cloud routine automation, Excel/VLOOKUP data modeling

Repository Structure:

  • Threat-actor tracking: 29 APT/state-sponsored groups and 25 ransomware groups with documented MENA targeting, each row citing a real, verifiable public source and tagged by sourcing confidence (high/medium/low) — revalidated via an independent fact-check pass that caught and corrected several sourcing errors before publication.
  • Country-specific subsets: Focused Saudi Arabia (4 groups) and Egypt (8 groups) subsets, each with a full MITRE ATT&CK technique breakdown per group and a Navigator layer heatmapping technique overlap across the group set, plus a dedicated financially-motivated-threat-actor discovery pass (a defensible negative result for KSA specifically, narrowing to one high-confidence hit — a $1.4B+ exchange heist — once broadened MENA-wide).
  • Sigma detection-coverage auditing: Cross-referenced every tracked technique against a 3,700+ rule Sigma corpus to classify Covered/Partial/Not-Covered status, then built a fully normalized per-rule mapping workbook (Rule Library + live VLOOKUP-joined Mapping sheet) so thousands of (group, technique, rule) rows don't duplicate a single byte of YAML text.
  • Monthly automation: A scheduled cloud routine incrementally updates the tracker — date-bounded discovery restricted to the window since the last run, conditional regeneration of expensive artifacts only when something actually changed, and a state file that makes the pipeline resumable and auditable.

Notable Engineering Decisions:

  • Trust but verify, always: An independent detection-engineer revalidation pass on Sigma coverage classifications caught a 16% error rate in the first-pass output — every coverage number was then recomputed deterministically rather than trusted from a single pass.
  • Designed around a known automation failure mode: A sibling routine's stored-config-vs-repo-file drift (editing a config file didn't update the live schedule) was avoided here by making the routine's stored config a thin pointer to a version-controlled file, so logic changes take effect automatically on the next run.

Automated Weekly Threat Intelligence Pipeline

Objective: Built a fully automated scheduled pipeline that fetches, triages, and operationalizes fresh threat intelligence reports weekly — producing structured Sigma rules and hunt hypotheses with zero manual analyst input per cycle and a mandatory human-review gate before any output reaches the main branch.

Tools & Tech: Automated orchestration platform (scheduled cloud routine), Sigma, KQL, MITRE ATT&CK, GitHub (branch + draft PR governance), Python

Pipeline Design:

  • Sources Layer: 38 curated TI outlets — 35 global vendors/DFIR shops plus 3 MENA-dedicated sources (CTM360, Resecurity, Help AG) — checked weekly against a strict 7-day publication window; stale reports are excluded unconditionally.
  • MENA-Region Prioritization: Up to 5 reports processed per cycle, ranked by MENA-region relevance — aligning pipeline output with the operational focus of the target environment.
  • 4-Stage Automated Cascade: TTP/IOC extraction (structured JSON with confidence scoring) → automated routing classifier (separates detection candidates from hunt candidates based on observability and FP manageability) → detection rule building + hunt hypothesis generation running in parallel.
  • Output Governance: Every run commits to a dated branch and opens a draft PR — never pushes to main directly, never auto-merges. Empty weeks produce no PR. The pipeline logic is version-controlled, making behavior fully auditable without touching any config.

Proof-of-Concept Case — APT34/OilRig:

  • Manually exercised against Check Point Research's Veaty/Spearal/CacheHttp.dll report (APT34/OilRig targeting Iraqi government infrastructure, 2024-09-11): 18 TTPs extracted at medium confidence → 6 detection candidates produced (5 built as Sigma rules; 1 correctly declined because the candidate was a decaying IOC unsuitable for a durable rule) + 11 hunt hypotheses generated.
  • Test run surfaced a gap in the scheduled routine (no regional weighting, no strict date window) that was corrected before automation went live.

Hunt-to-Detection Closure Loop

Objective: Built a structured automated workflow that prevents threat-hunting findings from dead-ending as one-off write-ups — routing confirmed hunt findings through detection engineering, then validating the resulting rule with a purple team simulation before closing the loop.

Tools & Tech: Multi-stage automation pipeline, Sigma, KQL, MITRE ATT&CK, Atomic Red Team / MITRE CALDERA

Workflow:

  • Gate-check routing: Each hunt finding is evaluated before progressing — only findings confirmed repeatable and observable continue to rule-building; active compromise indicators are escalated directly to incident response instead.
  • Detection Engineering: Produces a Sigma/KQL rule from the hunt's confirmed TTPs, data sources, and query logic — or an explicit visibility-gap flag if the behavior isn't yet observable (an unfireable rule creates false confidence and is worse than an honest gap).
  • Purple Team Validation: Simulates the exact technique using Atomic Red Team or equivalent in a non-production environment and confirms the SIEM/EDR actually alerts — "we built a rule" is not the same as "we confirmed it fires."
  • Failure Handling: Distinguishes a logic gap (rule logic is wrong — fix and re-test once) from a pipeline/ingestion gap (log source or collection issue — document and close as a separate finding rather than looping indefinitely on something detection engineering cannot fix).
  • Closure Feedback: Logs the validated status so the next hunt cycle deprioritizes re-hunting the same TTP and redirects effort to the next visibility gap.

Threat Hunting Queries & MITRE ATT&CK Detection Library

Objective: Developed and operationalized a library of threat-hunting queries and detection rules mapped to MITRE ATT&CK tactics and techniques, enabling proactive APT detection across enterprise environments.

Tools Used: IBM QRadar, Splunk, Elastic Stack (ELK), CrowdStrike, Sigma, MITRE ATT&CK Navigator

Methodology:

  • "Know Normal to Hunt Evil" Baseline (SANS FOR508): Built per-process baselines covering expected parent/path/account/instance-count/start-time for core OS processes (lsass, svchost, explorer, winlogon, etc.) — deviations from baseline (wrong parent, misspelled name, wrong path) surface masquerading malware and process injection attempts without relying on signature matching.
  • Three-Tier Hypothesis Framework: Structured hunt missions across three tiers — intelligence-led (actor TTP reports drive the hypothesis), TTP-driven (ATT&CK technique selected, hunt designs the data query), and anomaly-based (statistical deviation from established behavioral baseline).
  • ATT&CK Coverage Gap Analysis: Used MITRE ATT&CK Navigator to map existing detection rules against the full technique matrix, identifying blind spots by tactic — prioritizing coverage expansion in Initial Access, Lateral Movement, and Credential Access where APT dwell time is highest.
  • ATT&CK-Mapped Query Development: Created custom Sigma rules and SIEM correlation queries targeting high-value techniques: Kerberoasting (T1558.003), DCSync (T1003.006), Pass-the-Hash (T1550.002), WMI persistence (T1047), Golden Ticket (T1558.001), scheduled task abuse (T1053.005), PowerShell execution (T1059.001), and lateral movement via PsExec/Scheduled Tasks/WMI.
  • Telemetry Correlation: Correlated Windows event logs (4624/4625/4648/4698/4702/4768/4769), Sysmon (Event IDs 1/3/7/8/10/11/13), EDR telemetry, and network flow data — building multi-source detection logic that degrades gracefully when individual log sources are unavailable.
  • Hunt-to-Detection Handoff: Formalized findings routing — confirmed repeatable findings trigger a structured handoff to detection engineering; active compromise indicators route directly to incident response; inconclusive findings return to the hunt queue for further investigation.
  • Detection Tuning: Iteratively refined rules against production telemetry to reduce false positives while broadening detection coverage — scoring each candidate on Coverage, Durability, Complexity, Confidence, FP rate, and Actionable content before promoting to production.

SOC Automation & Incident Response Playbooks

Objective: Built automated incident-response workflows and a structured multi-phase IR chain aligned to NIST SP 800-61 and SANS PICERL, standardizing detection through closure — including mandatory post-incident detection validation to confirm exposed gaps are actually fixed before an incident is closed.

Tools Used: IBM Resilient SOAR, Python, Bash, QRadar, MITRE ATT&CK

Methodology:

  • Classification-First Approach: All incidents are classified (P1–P4) before any downstream action is triggered — severity drives SITREP cadence, escalation path, and whether the full IR chain is warranted. A P4/informational finding exits at triage; the full chain is never run against noise.
  • Multi-Phase IR Chain (NIST SP 800-61 + SANS PICERL aligned): Classify and open SITREP → parallel DFIR forensics + artifact analysis (timeline, root cause, persistence/lateral-movement path) → SOC leadership escalation (confirm/upgrade severity, executive bridge decision) → BC/DR activation (conditional — only on critical system down, backups targeted, or ransomware confirmed) → Post-Incident Report (root cause, timeline, remediation, lessons learned) → purple team detection validation → executive reporting.
  • Mandatory Detection Validation: Confirmed TTPs from forensic findings are simulated post-incident to verify that existing detections would have caught the technique — or that any new rule built in response actually fires. An incident that closes without confirming the detection gap is fixed is a recurrence waiting to happen.
  • Playbook Development: Created IR playbooks for phishing, ransomware, lateral movement, and identity compromise — each mapped to MITRE ATT&CK tactics/techniques with explicit containment actions, evidence-collection checklists, and SOAR-triggerable decision points.
  • SOAR Integration: Automated alert triage, IOC enrichment, and containment actions using IBM Resilient SOAR — reducing manual analyst steps and accelerating MTTR.
  • Python Scripting: Developed scripts for log parsing, IOC extraction, and ticket generation to eliminate redundant SOC workflows and feed structured data back into the detection feedback loop.

Comprehensive Vulnerability Assessment

Objective: Conducted a vulnerability assessment on local and external-facing assets to identify and mitigate security risks, leveraging both passive and active reconnaissance techniques.

Tools Used: Shodan, Nmap, Dirsearch, Sublist3r, Xray, Metasploit

Methodology:

  • Passive Information Gathering with Shodan: Used Shodan to perform passive reconnaissance, identifying publicly exposed services, devices, and their associated metadata. Collected information on open ports, service banners, and potential vulnerabilities for external-facing assets.
  • Active Information Gathering with Nmap: Conducted network scans using Nmap to enumerate open ports, running services, and operating system information. Used Nmap Scripting Engine (NSE) to detect vulnerabilities such as outdated software versions, default credentials, and misconfigurations.
  • Subdomain Enumeration: Used Sublist3r to discover additional subdomains, expanding the attack surface for potential vulnerabilities.
  • Directory Scanning with Dirsearch: Performed directory brute-forcing on web servers to locate hidden or sensitive directories, including admin panels and backup files.
  • Vulnerability Scanning with Xray: Utilized Xray scanner to identify critical vulnerabilities in web applications, including SQL injection, Cross-Site Scripting (XSS), and file inclusion vulnerabilities.
  • Exploitation and Post-Exploitation with Metasploit: Leveraged Metasploit Framework to simulate exploitation of identified vulnerabilities in a controlled environment, including privilege escalation and lateral movement.

Outcome:

  • Successfully uncovered 8 critical vulnerabilities, including exposed sensitive directories, SQL injection, XSS, and file upload vulnerabilities in web applications.
  • Provided a detailed report with prioritized mitigation strategies, recommending actions such as patch management, access control updates, and enhanced monitoring.
  • Strengthened the security posture of the organization by resolving all critical issues and improving overall resilience against potential attacks.
